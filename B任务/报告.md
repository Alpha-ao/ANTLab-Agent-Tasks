# B任务报告

## 问题与修复

原样机有三处问题：

| 问题 | 原因 | 改动 |
|---|---|---|
| 换了版本仍返回旧结果 | 缓存只按问题文字区分 | 同时检查文档、版本、参数、资料内容和草稿 |
| 指定范围有资料却没找到 | 先从全库截取，再筛选范围 | 先限定文档和版本，再排序截取 |
| 引用能定位就显示已支持 | 把编号合法当成内容核验 | 分开显示定位状态和语义状态，未核验就注明 |

原样机、题目资料与固定草稿均保留。修复没有改写草稿答案，也没有硬编码题号。
这里是合成数据的离线重放，运行耗时不能当作模型推理速度。

## 同一症状的原因对照

目标请求固定为alpha/v2、k=1，症状是“证据为空”，但资料中确实有匹配的b02。
先用原程序产生一个空结果缓存，再将同一缓存副本交给四组。运行前保存各组预测。

| 条件 | 命中旧缓存 | 证据结果 |
|---|---|---|
| 原版 | 是 | 空 |
| 只修缓存 | 否 | 空 |
| 只修检索 | 是 | 空 |
| 两处都修 | 否 | b02 |

旧缓存会直接复用空结果；绕过它后，错误的截取顺序又会重新产生空结果。两种机制可以共同存在。
冷启动和k=2对照进一步区分了它们的作用。输入、缓存、预测和实际返回见[同症状实验记录](../runs/advanced_b/same_symptom/)。
这项实验是在读过源码后设计的，不属于未知故障盲测。首轮不同症状的对照另行保留，没有改写成同症状实验。

## 外部信息辅助诊断

使用DeepSeek V4.1 Flash，对3类故障分别提供“现象”“现象＋错误类别”“再加日志和原文”，共9次真实请求。
具体证据让诊断可以对应实际版本、候选资料和原文；但仅有现象时，模型有时也能提出正确的候选原因。
版本案例中的“返回30秒”有歧义，曾被理解为响应耗时，因此不能据此计算反馈提升率。

这9次仅作为辅助观察，没有测试自动改代码，也没有证明外部反馈普遍提高改错能力。原始返回全部保留，未追加调用追求更好的结果。
