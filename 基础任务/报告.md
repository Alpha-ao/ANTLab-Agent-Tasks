# 基础任务报告

## 做了什么

程序接收一个问题和若干资料，整理后交给DeepSeek，返回答案和引用编号。题包提供4道开发题和8道评测题。
题目包括算比例、算差值、按条件选方案、查版本，以及资料不足时说明无法判断。

## 实验

首轮固定模型和参数，对8道评测题比较原顺序、两种换序、只选两段资料、重新排序五种条件，共40次请求。
输入、返回、耗时与引用全部保存。排序方法只调整资料顺序，没有写入题目答案。

| 首轮条件 | 暂定答对 |
|---|---:|
| 原顺序 R0 | 4/8 |
| 换序 R1 | 4/8 |
| 换序 R2 | 3/8 |
| 只选两段 K | 1/8 |
| 排序改进 | 3/8 |

首轮排序没有提高结果。后续增加通用计算检查提示，并启用low思考模式；在完整资料的四种条件下均为8/8。它增加了推理预算，而且是在看过这些题后进行的改进，不能当作盲测，也不能把改善归功于排序。

额外的长文本、缺资料检查中，16条明确案例通过；另有1条测试本身存在歧义，保留原记录，没有删掉重算。

## 怎么核对

从[首轮逐题表](../results/results.csv)或[改进逐题表](../results/exploration.csv)找到run_id，再到原始请求目录查看实际输入和返回。
引用编号存在，只能说明可以定位；还要读对应原文，确认它是否支持答案。

详细过程见[首轮记录](../report-basic-v1.md)和[改进记录](../report-v2.md)。

## 完成范围

代码、真实调用、结果保存、网页预览与回放均已实现。采用基于原文的候选判分规则，尚无独立人工标注。
只选两段资料仍可能漏掉关键条件，不作为默认方案。当前默认使用完整资料、新提示词和low思考模式。
模型服务变化可能影响再次调用的结果；已有日志可以离线核对。
